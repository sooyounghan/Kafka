### 카프카 스트림즈
-----
<div align="center">
<img src="https://github.com/user-attachments/assets/cc08f456-9ffc-49e1-b854-1e0ee31619f9" />
</div>

1. 카프카 스트림즈는 토픽에 적재된 데이터를 실시간으로 변환하여 다른 토픽에 적재하는 라이브러리
   - 스트림즈는 카프카에서 공식적으로 지원하는 라이브러리
   - 매번 카프카 버전이 오를 때마다 스트림즈 자바 라이브러리도 같이 릴리즈 됨
   - 그렇기 때문에, 자바 기반 스트림즈 애플리케이션은 카프카 클러스터와 완벽하게 호환되면서 스트림 처리에 필요한 편리한 기능들을 제공

2. 스트림즈 애플리케이션 또는 카프카 브로커의 장애가 발생하더라도 정확히 한 번(Exactly Once) 할 수 있도록 장애 허용 시스템(Fault Tolerant System)을 가지고 있어서 데이터 처리 안정성이 매우 뛰어남
3. 카프카 클러스터를 운영하면서 실시간 스트림 처리를 해야하는 필요성이 있다면, 카프카 스트림즈 애플리케이션으로 개발하는 것을 1순위로 고려하는 것이 좋음

4. 프로듀서와 컨슈머를 조합하지 않고, 스트림즈를 사용해야 하는 이유
   - 스트림 데이터 처리에 있어서 필요한 다양한 기능을 스트림즈DSL로 제공하며, 필요하다면 프로세서 API를 사용하여 기능을 확장할 수 있기 때문임
   - 컨슈머와 프로듀서를 조합하여 스트림즈가 제공하는 기능과 유사하게 만들 수 있음
   - 💡 그러나 스트림즈 라이브러리를 통해 제공하는 단 한 번의 데이터 처리, 장애 허용 시스템 등의 특징들은 컨슈머와 프로듀서의 조합만으로 완벽하게 구현하기는 어려움
   - 다만, 스트림즈가 제공하지 못하는 기능을 구현할 때는 컨슈머와 프로듀서를 조합하여 구현하면 좋음
     + 예를 들어, 소스 토픽(사용하는 토픽)과 싱크 토픽(저장하는 토픽)의 카프카 클러스터가 서로 다른 경우는 스트림즈가 지원하지 않으므로, 이 때는 컨슈머와 프로듀서 조합으로 직접 클러스터를 지정하는 방식으로 개발할 수 있음

### 스트림즈 내부 구조
-----
<div align="center">
<img src="https://github.com/user-attachments/assets/460085b5-2a42-4b24-9b1c-bcc9e08a1be4" />
</div>

1. 스트림즈 애플리케이션은 내부적으로 스레드를 1개 이상 생성할 수 있으며, 스레드는 1개 이상 태스크를 가짐
2. 스트림즈의 태스크(Task) : 스트림즈 에플리케이션을 실행하면 생기는 데이터 처리 최소 단위
   - 만약 3개의 파티션으로 이루어진 토픽을 처리하는 스트림즈 애플리케이션을 실행하면 내부에 3개의 태스크가 생김
   - 컨슈머의 병렬처리를 위해 컨슈머 그룹으로 이루어진 컨슈머 스레드를 여러 개 실행하는 것과 비슷하다고 볼 수 있음
3. 카프카 스트림즈는 컨슈머 스레드를 늘리는 방법과 동일하게 병렬 처리를 위해 파티션과 스트림즈 스레드 (또는 프로세스) 개수를 늘림으로써 처리량을 늘릴 수 있음

### 소스 프로세서, 스트림 프로세서, 싱크 프로세서
-----
<div align="center">
<img src="https://github.com/user-attachments/assets/a3eab8e0-9622-4360-8643-010958380bd6" />
</div>

1. 프로세서에는 소스 프로세서, 스트림 프로세서, 싱크 프로세서 3가지가 존재
2. 소스 프로세서 : 데이터를 처리하기 위해 최초로 선언해야 하는 노드로, 하나 이상의 토픽에서 데이터를 가져오는 역할
3. 스트림 프로세서 : 다른 프로세서가 반환한 데이터를 처리하는 역항을 하며, 변환 / 분기 처리와 같은 로직이 데이터 처리의 일종이라고 볼 수 있음
4. 싱크 프로세서 : 데이터를 특정 카프카 토픽으로 저장하는 역할을 하며, 스트림즈로 처리된 데이터의 최종 정착지

### 스트림즈 DSL와 프로세서 API
-----
1. 스트림즈 DSL(Domain Specific Language)와 프로세서 API 2가지 방법으로 개발 가능
2. 스트림즈 DSL은 스트림 프로세싱에 쓰일 만한 다양한 기능들을 자체 API로 만들어놓았으므로 대부분 변환 로직을 어렵지 않게 개발할 수 있음
   - 만약 스트림즈 DSL에서 제공하지 않는 일부 기능들의 경우, 프로세서 API를 사용하여 구현할 수 있음

3. 스트림즈 DSL로 구현하는 데이터 처리 예시
   - 메세지 값을 기반으로 토픽 분기 처리
   - 지난 10분간 들어온 데이터 개수 집계

4. 프로세서 API로 구현하는 데이터 처리 예시
   - 메세지 값의 종류로 토픽을 가변적으로 전송
   - 일정한 시간 간격으로 데이터 처리
