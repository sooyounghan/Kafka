-----
### 정리
-----
1. 카프카 클러스터는 브로커들의 묶음이며, 클러스터는 1대 이상 브로커로 구성되어 있음
2. 카프카 브로커를 실행하기 위해 주키퍼가 필수 (3.0.0 부터는 제외 가능)
3. 프로듀서에서 전송된 데이터는 디렉토리에 저장
4. 브로커는 복제 / 컨트롤러 / 데이터 삭제 / 오프셋 저장 / 코디네이터 역할 수행
5. 1개의 주키퍼에는 여러 카프카 클러스터를 운영할 수 있음
6. 토픽은 1개 이상 파티션으로 구성되어 있음
7. 파티션은 FIFO 구조이지만, 컨슈머가 데이터를 가져가더라도 바로 삭제되지 않음
8. 컨슈머의 처리량을 늘리기 위해 파티션 개수를 늘릴 수 있음

-----
### 퀴즈
-----
1. 컨슈머가 가져간 데이터는 파티션에서 삭제됨 (X) : 파티션에서 삭제 되지 않음 (파티션 데이터가 삭제되는 것은 브로커가 어떤 Compact나 Delete를 cleanup.policy 정책에 따라 로그 세그먼트 단위로 데이터가 삭제)
2. 💡 카프카에서 데이터 복제의 단위는 토픽 (X) : 데이터의 복제 단위는 파티션
3. 💡 파티션은 1개의 리더 파티션과 1개 이상의 팔로워 파티션으로 이루어져 있음 (X) : 파티션은 1개의 리더 파티션을 가지며, 항상 1개 이상 팔로워 파티션을 가지는 것은 아님 (Replication Factor가 1인 경우, 리더 파티션만 존재)
4. 💡 프로듀서와 컨슈머는 팔로워 파티션과 통신하여 데이터 처리량을 늘릴 수 있음 (X) : 프로듀서와 컨슈머는 반드시 리더 파티션과 통신하며, 팔로워 파티션은 리더에 있는 데이터를 복제하는 용도로만 사용
5. 레코드는 타임 스탬프, 메세지 키, 메세지 값, 오프셋으로 이루어져 있음 (X) : 헤더도 포함
6. 다음 파티션에서 압축(Compact)이 실행된다면, 남은 모든 오프셋의 배열은?
