### 카프카 버로우
-----
1. 버로우는 링크드인에서 개발하여 오픈소스로 공개한 컨슈머 랙 체크 툴
   - REST API를 통해 컨슈머 그룹 별 컨슈머 랙을 확인할 수 있음

2. 외부 모니터링 툴을 사용하면 카프카 클러스터에 연결된 모든 컨슈머, 토픽들의 랙 정보를 한 번에 모니터링할 수 있다는 장점이 존재
3. 또한, 모니터링 툴들은 클러스터와 연동되어 컨슈머의 데이터 처리와 별개로 지표를 수집하기 때문에 데이터를 활용하는 프로듀서나 컨슈머 동작에는 영향을 미치지 않는다는 장점도 존재
4. 버로우는 다수의 카프카 클러스터를 동시에 연결하여 컨슈머 랙을 확인
   - 기업 환경에서는 카프카 클러스터를 2개 이상 구축하고 운영하는 경우가 많으므로 한 번의 설정으로 다수의 카프카 클러스터 컨슈머 랙을 확인할 수 있다는 장점 존재

### 컨슈머 랙 이슈 판별
-----
<div align="center">
<img src="https://github.com/user-attachments/assets/89dccf8f-eb93-485b-94e1-41fb78d62853" />
</div>

1. 버로우 기능 중 가장 돋보이는 것은 컨슈머와 파티션 상태를 단순히 컨슈머 랙의 임계치(Threshold)로 나타내지 않았다는 점
2. 특정 파티션의 컨슈머 랙이 특정 시점에 100만이 넘었다고 컨슈머 또는 파티션에 이슈가 있다고 단정 지을 수 없음
   - 프로듀서가 데이터를 많이 보내면 일시적으로 임계치를 넘어가는 현상이 발생할 수도 있기 때문임
3. 컨슈머 애플리케이션을 운영할 때, 컨슈머 랙이 임계치에 도달할 때마다 알람을 받는 것은 무의미한 일

-----
### 컨슈머 랙 평가(Evaluation)
-----
1. 버로우에서는 임계치가 아닌 슬라이딩 윈도우(Sliding Window) 계산을 통해 문제가 생긴 파티션과 컨슈머의 상태를 표현
2. 이렇게 버로우에서는 컨슈머의 랙 상태를 표현하는 것을 컨슈머 랙 평가(Evaluation)라고 부름
3. 컨슈머 랙과 파티션의 오프셋을 슬라이딩 윈도우로 계산하면 상태가 정해짐
   - 결과적으로 파티션의 상태를 OK, STALLED, STOPPED로 표현하고 컨슈머의 상태를 OK, WARNING, ERROR로 표현

4. 정상적인 경우
<div align="center">
<img src="https://github.com/user-attachments/assets/7fa97742-40c9-41c0-b9a9-c5e97e7def82" />
</div>

   - 일반적으로 컨슈머를 운영하면서 자주 볼 수 있는 그래프
   - 프로듀서가 지속적으로 데이터를 추가하므로 최신 오프셋은 계속해서 증가
   - 컨슈머는 데이터 처리를 하면서 때때로 컨슈머 랙이 증가하지만, 다시 0으로 줄어드는 추이를 볼 수 있음
   - 이런 경우 컨슈머가 정상적으로 동작한다고 볼 수 있으며, 버로우는 파티션 OK, 컨슈머도 OK로 상태를 나타냄

5. 컨슈머 처리량 이슈
<div align="center">
<img src="https://github.com/user-attachments/assets/b2fcf979-b8e3-40e7-bf38-8b2ecd5dea95" />
</div>

   - 프로듀서가 추가하는 최신 오프셋에 비해 컨슈머 오프셋이 따라가지 못하는 추이를 볼 수 있음
   - 최신 오프셋과 컨슈머 오프셋의 거리가 계속 벌어지면서 컨슈머 랙은 지속적으로 증가
   - 이러한 그래프가 나오는 이유는 컨슈머의 데이터 처리량이 프로듀서가 보내는 데이터 양에 비해 적기 때문임
   - 이 경우, 버로우는 파티션은 OK, 컨슈머는 WARNING 상태로 나타냄

6. 컨슈머 이슈
<div align="center">
<img src="https://github.com/user-attachments/assets/50869ad7-4cbf-410c-8d06-e40408e97599" />
</div>

   - 최신 오프셋이 지속적으로 증가하고 있지만, 컨슈머 오프셋이 멈춘 것 확인 가능
   - 이로 인해 컨슈머 랙이 급격하게 증가하는 모습을 볼 수 있음
   - 컨슈머가 어떠한 이유로 데이터를 더는 가져가지 않는 것으로, 이 경우 버로우는 파티션은 STALLED, 컨슈머는 ERROR 상태로 나타냄
     + 컨슈머 상태가 ERROR인 경우에는 컨슈머가 확실히 비정상 동작하고 있으므로, 이메일 / SMS / 슬랙 등 알람을 받고 즉각 조치해야 함

### 컨슈머 랙 모니터링 아키텍쳐
-----
<div align="center">
<img src="https://github.com/user-attachments/assets/a7d596f0-211d-452a-8a24-7df74bb1e817" />
</div>

1. 버로우를 통해 컨슈머 랙을 모니터링 할때는 이미 지나간 컨슈머 랙을 개별적으로 모니터링 하기 위해서 별개의 저장소와 대시보드를 사용하는 것이 효과적
2. 컨슈머 랙을 모니터링을 위해 사용할 수 있는 저장소와 대시보드는 다양하지만 빠르게, 무료로 설치할 수 있는 아키텍쳐를 제안
   - 버로우 : ```github.com/linkedin/Burrow```
   - 텔레그래프 : ```github.com/influxdata/telegraf```
     + REST API를 지속적으로 계속 호출하여 엘라스틱서치에 JSON 형태로 데이터를 저장
   - 엘라스틱서치 : ```www.elastic.co/kr```
     + 텔레그래프를 사용해 엘라스틱서치에 데이터 수집
   - 그라파나 : ```grafana.com```
     + 엘라스틱서치에 시간 순서로 데이터를 넣을 때, 시각화 하는 도구로 활용
   - 설치 방법 : ```blog.voidmainvoid.net/279```
